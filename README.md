# Edge-Cloud Request Dispatch for LLM Inference — Code and Reproduction Artifact

Simulation and analysis code for the paper **"When Does Structure Beat Information? A Factorial Study of Edge-Cloud Request Dispatch for LLM Inference"** (Apoorva Tripathi).

This repository contains everything needed to reproduce every table and figure in the paper from the public trace source: a modified iFogSim2 fork implementing the dispatch policies and topology, and the Python pipeline that prepares workloads, runs the experiment grid, and computes every reported statistic.

## Repository layout

```
iFogSim/                  Fork of iFogSim2 (github.com/Cloudslab/iFogSim, commit 5f68d39)
  src/org/paper2/         All original code for this paper (see below)
  src/org/fog/entities/   Three files modified/added in the base framework
                          (ControllerComponent.java, MicroserviceFogDevice.java,
                          ServiceDiscovery.java) -- everything else is unmodified upstream
  jars/                   Third-party dependencies (Apache Commons Math, etc.)
src/                      Python analysis pipeline
  prepare_workload.py     Chronological windowing, capacity-relative and
                           utilization-matched load scaling
  tune_hybrid.py          Tuning-window-only threshold (theta) selection
  run_grid.py             Parallel grid execution (six named experiment sets)
  analyze.py              Metric computation, bootstrap CIs, paired Wilcoxon
                           tests, Holm-Bonferroni correction, interaction contrast
  make_figures.py         Both manuscript figures
  make_figures_journal.py Same figures without an embedded caption title, for
                           journals that require captions to live in the
                           manuscript text only
data/                      NOT included -- see "Get the data" below (git-ignored)
results/                   NOT included -- machine-generated by running the
                           pipeline below (git-ignored)
```

### What's actually original to this paper

Under `iFogSim/src/org/paper2/`:

- `workload/` — trace-driven request injection (`LLMTraceSensor`, `LLMTuple`, `TraceDistribution`)
- `topology/` — the three-scale (T1/T2/T3) edge-cloud topology builder (`Paper2Topology`)
- `dispatch/` — all ten dispatch policies (P1–P10) plus the P6-NS ablation variant (`Dispatchers`, `DispatchContext`, `TupleAwareLoadBalancer`)
- `placement/` — fixed, uniform service placement (`StaticPlacementLogic`)
- `harness/` — the per-run simulation driver and JSON-emitting result harness (`ExperimentRunner`, `Paper2Controller`, `Calibration`, `RequestLog`)

Everything else under `iFogSim/` is the upstream iFogSim2 framework, unmodified except for three files in `src/org/fog/entities/` (noted above and in `LICENSE`).

## Build the simulator

```
cd iFogSim
find src -name "*.java" > sources.txt
javac -nowarn -cp "jars/*;jars/commons-math3-3.5/*" -d bin @sources.txt
```

(On Linux/macOS, replace the `;` classpath separator with `:`.)

## Get the data

The paper uses the public, CC-BY-licensed Azure LLM Inference production traces. They are not included in this repository (1.8 GB total) — download them yourself:

```
mkdir -p data && cd data
curl -sL -o AzureLLMInferenceTrace_conv_1week.csv \
  https://github.com/Azure/AzurePublicDataset/releases/download/dataset-llm-2024/AzureLLMInferenceTrace_conv_1week.csv
curl -sL -o AzureLLMInferenceTrace_code_1week.csv \
  https://github.com/Azure/AzurePublicDataset/releases/download/dataset-llm-2024/AzureLLMInferenceTrace_code_1week.csv
```

Verify against the checksums the paper reports (Section 11): `AzureLLMInferenceTrace_conv_1week.csv` MD5 `2593e402e4b665c2fab4022e3e30b68f` (1,135,195,393 bytes, 27,304,000 lines); `AzureLLMInferenceTrace_code_1week.csv` MD5 `2ff59fd545186a9d6f308a7a16b851fd` (691,989,454 bytes, 16,803,696 lines).

## Reproduce every result

Run from the project root, in order:

```
# 1. Prepare workload windows (chronological, capacity-relative, utilization-matched)
python src/prepare_workload.py --trace conv --n-sites 4 --seeds 42 43 44 45 46 --loads 0.5 1.0 2.0
python src/prepare_workload.py --trace code --n-sites 4 --seeds 42 43 44 45 46 --loads 0.5 1.0 2.0
python src/prepare_workload.py --trace conv --n-sites 2 --seeds 42 43 44 45 46 --loads 1.0   # T1 ablation
python src/prepare_workload.py --trace conv --n-sites 8 --seeds 42 43 44 45 46 --loads 1.0   # T3 ablation

# 2. Tune the hybrid's threshold theta (tuning window only, seed 42)
python src/tune_hybrid.py --trace conv --mean-gen 112.99 --seed 42   # -> theta=38000
python src/tune_hybrid.py --trace code --mean-gen 26.59 --seed 42    # -> theta=14000

# 3. Run the full experiment grid (1,415 completed runs + 15 documented non-completions)
python src/run_grid.py --set main --workers 10        # 360 runs: main conv/T2 grid
python src/run_grid.py --set code --workers 6         # 360 configs: code trace (345 complete, 15 DNC at P1/2.0x)
python src/run_grid.py --set topo --workers 10        # 240 runs: T1/T3 ablation
python src/run_grid.py --set oracle_abl --workers 6   # 90 runs: P8, both traces
python src/run_grid.py --set factorial --workers 6    # 180 runs: P9/P10, both traces
python src/run_grid.py --set calib --workers 10       # 200 runs: calibration sensitivity

# 4. Figures
python src/make_figures.py            # results/figures/{token_distributions,sla_violation_curve}.png
python src/make_figures_journal.py    # same, without an embedded caption title

# 5. Every table in the paper
python src/analyze.py --trace conv --topo T2            # Tables 3, 4
python src/analyze.py --trace code --topo T2             # Table 6
python src/analyze.py --trace conv --topo T1             # Table 7, T1 row
python src/analyze.py --trace conv --topo T3             # Table 7, T3 row
python src/analyze.py --trace conv --topo T2 --sig 2.0   # Table 5, significance tests
python src/analyze.py --trace code --topo T2 --sig 2.0   # Table 6b, code-trace factorial and interaction
python src/analyze.py --trace conv --topo T2 --calib     # Table 8
```

No table or figure in the paper is hand-computed or hand-transcribed — every number is read directly from a script-emitted JSON file.

## Random seeds

Seeds `{42, 43, 44, 45, 46}` vary both per-request Bernoulli thinning (which trace arrivals survive rate-scaling) and site assignment. Results are aggregated across all 5 seeds for every reported configuration, nested under 3 distinct, non-overlapping evaluation windows. See the paper's Section 6.3 for the exact statistical treatment of this nested structure (in particular, why the 15 resulting runs per configuration are not treated as 15 independent samples).
